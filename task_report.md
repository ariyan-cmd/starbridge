# Task report

The one stop for why a decision was taken and what it cost. Newest entries go at the top of each section. Update it in the same commit as the change it records.

Entry rules:
- Decisions get an ID (D-001, ...) and are never deleted. If reversed, add a new decision that supersedes the old one.
- Every number has a date and a setup. Unmeasured items say `pending`.
- Cost means what we give up or pay: RAM, flash, time, features, flexibility.

| D-017 | 2026-11-15 | Issue #9 identity: node ID is `chipId()` (`ESP.getChipId()`). Name is a 18-byte record (magic 0xB5, then 17 bytes NUL-terminated name) at offset 0 of a new `hal/board` NV store, validated on load (1..16 printable ASCII) with fallback to `NODE_NAME_DEFAULT` ("starbridge", overridable in `local_config.h`). The NV store is emulated EEPROM, 64 bytes, opened once and never closed; offsets are listed in `hal/board.h`. Caps: I2C scan of 0x08..0x77 sets `CAP_DISPLAY` if `OLED_I2C_ADDR` ACKs and `CAP_IMU` if `MPU_I2C_ADDR` ACKs; `SENSOR_CAPS` in config adds `CAP_TEMP`/`CAP_LIGHT` (other bits masked off). `hal/i2c_scan` added | EEPROM is in the core and needs no filesystem mount; 18 bytes do not need LittleFS. The magic byte tells erased flash (0xFF) from a saved name. One shared, always-open EEPROM image is the only safe way to share it, see the review row in Numbers | LittleFS file (mount cost, flash partition), MAC-based ID (48-bit, does not fit `src_id`), per-call `EEPROM.begin/end` in identity (first version, wiped other owners), probing only the two known addresses (no scan log) | 64 B of RAM held for the EEPROM image for the whole run. Each write erases and rewrites one 4 KB flash sector, and power loss between erase and write loses the name (falls back to the default). `getChipId()` is 24 bits of the MAC, so two nodes could in theory share an ID. CAP_IMU means "something ACKs at MPU_I2C_ADDR", not that WHO_AM_I passed. Temporary `name <x>` serial command in the sketch until the console (#13); it needs the monitor to send a newline |
| D-016 | 2026-11-15 | Issue #5 codec: `codecBuild/codecParse/codecInit(firstSeq)`. Parse checks short frame, version, type, then length (payload_len must fit the frame and match the type's exact size; CMD needs 1..240). Trailing bytes after the payload are ignored. Duplicate drop is a 16-slot ring of recent (src_id, seq) shared by all peers, filled only by accepted packets. The seq counter starts at a caller-given value | Exact per-type sizes stop a short HELLO being read as a full struct. A shared ring is the smallest table with no heap. A random first seq stops peers dropping our boot HELLO when (src, 0) from our last boot is still in their ring | Per-peer last-seq (needs the peer table, breaks on reboot), dedupe outside parse, `payload_len == frame` strict check | 96 B table. With many chatty peers a duplicate older than 16 packets gets through. Any future payload size change needs `sizeOk` updated (static_asserts in protocol.h flag it). Caller must seed `codecInit` with a random value (ESP: `os_random()`), wired in #16 |

WHO_AM_I reads 0x68 even with AD0 high, so it does not prove the address |
