# Star-Bridge v0.1 plan

Copied from the project doc "v0.1 plan". Edit the project doc first, then sync this copy.

## Build in V0.1

1. **Identity and capability manifest.** Each node gets an ID from its MAC or chip ID and a name. On boot it scans I2C and registers what it finds (SSD1306 at 0x3C, the accelerometer at its address). Analog and digital sensors like a DHT or LDR can't be auto-detected, so those go in a config line. The node announces its capabilities to peers, for example `{display, imu, temp}`.
2. **Accelerometer gestures as events.** Shake, tap, tilt, pickup, face-down and freefall are all cheap to detect from raw acceleration. They are the robot's main input and the most natural thing to send across the network.
3. **OLED face.** Eyes that look in the tilt direction, blink, go dizzy on shake and sleep when face-down. Add a status screen (node name, peer count, RSSI) that you can switch to with a gesture.
4. **Peer discovery, heartbeat and timeout.** Nodes broadcast HELLO on boot and a heartbeat every few seconds. Each node keeps a peer table and drops peers after N missed beats.
5. **Event propagation.** A gesture on node A produces an event that B sees. The demo is shaking one robot and watching the other's face react. Also publish temperature periodically so any node can display a peer's reading.
6. **Serial console.** Commands like `peers`, `caps`, `set name`, `send`.

## Transport: ESP-NOW

No router or IP stack, low latency, works on ESP8266 and ESP32. Limits: 250-byte payload, no multi-hop. Multi-hop is acceptable for V0.1, but the packet header carries a `ttl` field so flooding or routing can be added later without changing the wire format.

Envelope: `[version | type | src_id | seq | ttl | payload_len | payload]`. Message types: HELLO, BEAT, EVENT, TELEMETRY, CMD.
